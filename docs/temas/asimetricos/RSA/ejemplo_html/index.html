Definición

¿Qué es RSA?

Algoritmo de cifrado asimétrico publicado en 1977 por Rivest, Shamir y Adleman (MIT). Su seguridad se basa en la dificultad de factorizar el producto de dos números primos grandes.

  • Soporta cifrado, firmas digitales y autenticación
  • Mínimo recomendado: 2048 bits; nuevo software: 3072 bits
  • Para software moderno, considerar Ed25519 o ECDSA-P256

Usos en la Práctica

RSA no cifra datos grandes directamente en producción:

  • TLS: autentica el certificado del servidor; intercambio de claves via ECDHE desde TLS 1.3
  • Cifrado híbrido: RSA cifra una clave AES; AES cifra los datos
  • Firmas de código: RSA-PSS para binarios y actualizaciones
  • SSH / PGP: autenticación (Ed25519 es preferido hoy)
Matemáticas

Principios Matemáticos

Generación de Claves

1
Elegir dos primos grandes p y q

Ejemplo: p = 61, q = 53

2
Módulo público: n = p × q

n = 61 × 53 = 3233

3
Función de Euler: φ(n) = (p−1)(q−1)

φ(3233) = 60 × 52 = 3120 (secreto)

4
Exponente público e coprimo con φ(n)

gcd(17, 3120) = 1 → e = 17 (típicamente 65537)

5
Exponente privado d = inverso modular de e

17 × d ≡ 1 (mod 3120) → d = 2753

Cifrado y Descifrado

C = Me mod n

Cifrado con clave pública (n, e)

M = Cd mod n

Descifrado con clave privada (n, d)

¿Por qué funciona?
e × d ≡ 1 (mod φ(n)) garantiza que Med ≡ M (mod n) por el Teorema de Euler.

Ejemplo numérico (p=61, q=53)

Clave pública (n, e)(3233, 17)
Clave privada (n, d)(3233, 2753)

Base de la Seguridad — Factorización

RSA-1024
Factorizable con ~$10M USD de hardware (estimado 2010). Inseguro.
RSA-2048 (~112 bits)
Mínimo aceptable. Requiere >10¹⁵× más esfuerzo que RSA-1024.
RSA-3072 (~128 bits)
Recomendado hoy. El mejor ataque clásico: General Number Field Sieve (GNFS).
Esquemas de Padding

Padding — Crítico para la Seguridad

RSA "Textbook" sin padding es INSEGURO: es determinístico (mismo mensaje → mismo cifrado), malleable y vulnerable a múltiples ataques. Nunca usar en producción.

PKCS#1 v1.5 — Legado y Vulnerable

Formato: 0x00 0x02 [rnd] 0x00 [M]

  • Estándar de 1993 — ampliamente implementado
  • Vulnerable a Bleichenbacher (1998): ~1 millón de consultas adaptativas para recuperar el texto plano si el servidor devuelve errores diferenciados
  • ROBOT Attack (2017): afectó Facebook, PayPal, F5, Citrix, Cisco
Nunca usar PKCS#1 v1.5 para cifrado en sistemas nuevos.

RSA-OAEP — Cifrado Correcto

Optimal Asymmetric Encryption Padding (PKCS#1 v2.1)

  • Usa función hash + bytes aleatorios → probabilístico
  • El mismo mensaje produce cifrados distintos cada vez
  • Provablemente seguro bajo el modelo de oráculo aleatorio
  • RSA-2048+OAEP(SHA-256) → máximo 190 bytes de datos reales

RSA-PSS — Firmas Correctas

Probabilistic Signature Scheme (PKCS#1 v2.1)

  • Agrega sal aleatoria al proceso de firma
  • Mismo mensaje → firmas distintas cada vez
  • Provablemente seguro bajo supuestos estándar
Seguridad

Ataques a RSA

Bleichenbacher (1998) / ROBOT (2017)

Si el servidor retorna errores diferentes según si el padding PKCS#1 v1.5 es válido, un atacante recupera el texto plano en ~1 millón de consultas adaptativas.

ROBOT afectó Facebook, PayPal, F5, Citrix, Cisco.

✓ Usar RSA-OAEP. Retornar siempre el mismo error de descifrado.

Timing Attack — Paul Kocher (1996)

La exponenciación modular tarda distinto según los bits de d. Midiendo tiempos de muchas operaciones, se puede reconstruir la clave privada bit a bit.

✓ Implementaciones de tiempo constante (RSA blinding). Usar OpenSSL, libsodium.

Fault Attack en RSA-CRT

RSA usa el Teorema Chino del Resto para acelerar el descifrado. Un error de hardware inyectado en un cálculo expone la clave: gcd(firma_errónea − firma_correcta, n) = p en un paso.

✓ Verificar la firma/descifrado antes de retornar el resultado.

Factores Compartidos — Lenstra (2012)

0.2% de claves RSA en Internet compartían factores primos (routers con PRNG débil). gcd(n₁, n₂) = p revela ambas claves de inmediato.

✓ Usar CSPRNG de alta calidad. Evitar generación de claves en el arranque del sistema.

Errores Comunes

  • e = 3: si M³ < n, el cifrado es reversible con raíz cúbica
  • Sin passphrase en clave privada: archivo robado = clave comprometida
  • MD5/SHA-1 con RSA: SHA-1 roto (SHAttered, 2017). Usar SHA-256 mínimo
  • Módulo compartido entre usuarios: mensajes comunes son recuperables con el algoritmo de Euclides extendido
  • Entropía baja al arrancar: generar claves solo con hardware RNG o después del arranque completo
  • Implementar RSA desde cero: tiempo constante es difícil — usar OpenSSL, libsodium, cryptography
