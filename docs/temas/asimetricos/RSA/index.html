RSA

Rivest-Shamir-Adleman (1977)

Terminología


Public Key Encryption
  • Alice publica una llave pública derivada de una llave privada.
  • Todos pueden encriptar un mensaje para Alice usando la llave pública
  • Solo Alice puede descifrar el mensaje usando la llave privada.

Key Agreement

Los involucrados intercambian llaves públicas en un canal inseguro para establecer una llave secreta.


Digital Signature
  • Alice publica la llave pública derivada de la llave privada.
  • Alice firma el mensaje usando la llave privada
  • Cualquier persona puede validar el mensaje usando la llave pública

Definición

¿Qué es RSA?

  • Algoritmo de cifrado asimétrico publicado en 1977
  • Inventado por Rivest, Shamir y Adleman (MIT)
  • Su seguridad se basada en la dificultad de factorizar el producto de dos números primos grandes
  • Soporta cifrado de datos, firmas digitales y autenticación
  • Actualmente se recomienda el uso de keys de al menos 2048 bits para seguridad a largo plazo
  • Se recomienda que todo nuevo software debe usar 3072 bits o migrar a ECC.

Aplicación en la Práctica

RSA es un algoritmo que no cifra datos directamente, sino que cifra claves simétricas (AES) que luego cifran los datos reales.:

  • TLS: RSA autentica el servidor (certificado X.509), pero el intercambio de claves usa ECDHE desde TLS 1.3
  • Cifrado híbrido: RSA cifra una clave AES simétrica; AES cifra los datos
  • Firmas de código: RSA-PSS para firmado de binarios, actualizaciones de software

¿Cómo Funciona RSA?

Operación basada en un solo sentido

FÁCIL — Multiplicar dos primos
61 × 53 = 3233

p × q = n

Una calculadora lo hace en microsegundos.

DIFÍCIL — Factorizar el resultado
3233 = ? × ?

En RSA-2048, n tiene 617 dígitos.

RSA publica n. Oculta p y q. Sin ellos, nadie puede calcular la llave privada.

Generación de Claves

1. Elegir dos primos grandes p y q al azar — nunca se publican p=61, q=53
2. Calcular n = p × q. — es el número público n = 3233
3. Calcular φ(n) = (p−1)(q−1) — Función de Euler (z)
Cuántos números entre 1 y n no comparten factores con n. Permanece secreto φ = 3120
4. Elegir e (k): Máximo común divisor con φ(n) k = 17
5. Calcular d (j): el inverso matemático de e — cumple que k × j ≡ 1 (mod φ(n)). Es la llave privada d = 2753
Llave pública: (n=3233, e=17)
Llave privada: (n=3233, d=2753)

Cifrar y Descifrar

Todo RSA se reduce a exponenciación modular con la llave correcta:

CIFRAR — llave pública (e, n)
C = Me mod n
M = 65  (mensaje como número)
C = 6517 mod 3233 = 2790

Cualquier persona puede cifrar usando la llave pública.

DESCIFRAR — llave privada (d, n)
M = Cd mod n
C = 2790  (cifrado recibido)
M = 27902753 mod 3233 = 65

Solo quien tiene d puede descifrar.

¿Por qué funciona? e y d son inversos entre sí mod φ(n).
Aplicar ambos cancela la operación: Me·d ≡ M (mod n) — Teorema de Euler.
Sin d, revertir Me mod n requeriría factorizar n — computacionalmente inviable.

Limitación Práctica

RSA solo cifra datos pequeños
RSA-2048 → módulo de 256 bytes
Con padding OAEP → máximo 190 bytes de datos reales

No sirve para cifrar archivos, imágenes ni mensajes largos directamente.
Solución: cifrado híbrido
RSA cifra una clave AES de 32 bytes
AES cifra los datos reales de cualquier tamaño

Esquemas de Padding

El padding es crítico — RSA "textbook" sin padding es inseguro.

Glosario de Esquemas

PKCS
Public Key Cryptography Standards

Familia de estándares que especifican cómo usar RSA de forma interoperable. Publicados por RSA Security.
v1.5 (1993): legado, vulnerable.
v2.1 (2002): introduce OAEP y PSS.

OAEP
Optimal Asymmetric Encryption Padding

Esquema de padding para cifrado RSA. Mezcla el mensaje con bytes aleatorios y una función hash antes de cifrar. El mismo mensaje produce cifrados distintos cada vez — esquema probabilístico y probablemente seguro.

PSS
Probabilistic Signature Scheme

Esquema de padding para firmas RSA. Agrega una sal aleatoria al proceso de firma, produciendo firmas distintas del mismo mensaje. Análogo a OAEP pero para autenticidad, no confidencialidad.

ECDHE
Elliptic Curve Diffie-Hellman Ephemeral

Protocolo de intercambio de claves sobre curvas elípticas. Las claves son efímeras (desechadas por sesión), garantizando PFS. Reemplaza a RSA para key exchange en TLS 1.3.

PKCS#1 v1.5 — Legado y Vulnerable

  • Estándar de 1993 — ampliamente implementado
  • El padding tiene formato: 0x00 0x02 [bytes aleatorios] 0x00 [mensaje]
  • Vulnerable al ataque Bleichenbacher (1998): si el servidor devuelve un error diferente al recibir padding inválido, un atacante puede recuperar el texto plano en ~1 millón de consultas
  • Variantes del ataque aún son relevantes: ROBOT (2017) afectó Facebook, Paypal, F5, Citrix, etc.

Bleichenbacher — El Oráculo de Padding

¿Cómo recupera el atacante el texto plano en ~1 millón de consultas?

Atacante intercepta cifrado C del handshake TLS
bucle × ~1,000,000:
  C' = (se × C) mod n  ← transforma C algebraicamente
  Atacante → envía C' al servidor
  Servidor → responde una de dos:
    "RSA padding error"      → padding inválido (descarta)
    "bad record MAC"        → padding válido ✓ (info valiosa)
  Atacante estrecha el rango posible de M
Resultado: M = texto plano descifrado

La distinción entre tipos de error actúa como oráculo: responde preguntas de sí/no sobre M.
OAEP + respuesta de error uniforme e independiente del tipo de fallo cierra esta puerta.

RSA-OAEP — El Estándar Correcto para Cifrado

  • Optimal Asymmetric Encryption Padding (PKCS#1 v2.1)
  • Usa una función hash y bytes aleatorios para hacer el esquema probabilístico
  • El mismo mensaje produce diferentes cifrados cada vez
  • Provablemente seguro bajo el modelo de oráculo aleatorio
  • Siempre usar OAEP para cifrado RSA. Nunca PKCS#1 v1.5 en sistemas nuevos

RSA-PSS — El Estándar Correcto para Firmas

  • Probabilistic Signature Scheme (PKCS#1 v2.1)
  • Agrega sal aleatoria al proceso de firma — mismo mensaje, firmas distintas
  • Provablemente seguro bajo supuestos estándar
  • Usar RSA-PSS para firmas. PKCS#1 v1.5 para firmas es menos seguro aunque aún en uso (TLS legacy) 
from Crypto.PublicKey import RSA
from Crypto.Signature import pss
from Crypto.Hash import SHA256

key = RSA.generate(3072)
mensaje = b"Documento a firmar"
h = SHA256.new(mensaje)
firma = pss.new(key).sign(h)  # RSA-PSS

Generación de Claves (Python)

from Crypto.PublicKey import RSA

# Mínimo 2048 bits; recomendado 3072 bits para nuevo software
key = RSA.generate(3072)
private_key = key.export_key()           # Guardar cifrada con passphrase
public_key = key.publickey().export_key()
print("Clave privada:\n", private_key.decode())
print("Clave pública:\n", public_key.decode())

Cifrado con OAEP (Python)

from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_OAEP
from Crypto.Hash import SHA256

# Cargar clave pública del destinatario
public_key = RSA.import_key(open("public.pem").read())

# Cifrar con OAEP + SHA-256 (NO usar PKCS1_v1_5 para cifrado)
cipher = PKCS1_OAEP.new(public_key, hashAlgo=SHA256)
mensaje = b"Clave AES a transferir"
cifrado = cipher.encrypt(mensaje)
print("Cifrado:", cifrado.hex())

Descifrado con OAEP (Python)

from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_OAEP
from Crypto.Hash import SHA256

# Cargar clave privada
private_key = RSA.import_key(open("private.pem").read())

# Descifrar (usa la clave privada)
cipher = PKCS1_OAEP.new(private_key, hashAlgo=SHA256)
mensaje = cipher.decrypt(cifrado)
print("Mensaje:", mensaje.decode())

Longitud de Clave Recomendada

Tamaño RSA Bits de Seguridad Estado (2026)
1024 bits ~80 bits Inseguro
2048 bits ~112 bits Mínimo aceptable
3072 bits ~128 bits Recomendado
4096 bits ~140 bits Alta seguridad, más lento

Para software nuevo, considerar Ed25519 o ECDSA-P256 en vez de RSA

Firmas Digitales con RSA

  • Las firmas digitales RSA garantizan autenticidad, integridad y no repudio
  • El firmante aplica hash al documento y cifra el hash con su clave privada
  • Cualquiera verifica descifando la firma con la clave pública y comparando con el hash del documento
  • Usar RSA-PSS, no PKCS#1 v1.5, para nuevas firmas

RSA en TLS

En TLS 1.2 y anterior: RSA se usaba tanto para certificados como para intercambio de claves — sin PFS.

TLS 1.3 (RFC 8446): RSA solo autentica el certificado del servidor. El intercambio de claves es exclusivamente ECDHE o DHE — con PFS.

PFS — Perfect Forward Secrecy: las claves de sesión son efímeras y se descartan al cerrar la conexión.
TLS 1.2 sin PFS: capturar tráfico hoy + robar clave privada del servidor mañana = descifrado total de sesiones pasadas.
TLS 1.3 con ECDHE: aunque roben la clave del servidor, las sesiones pasadas son irrecuperables — las claves efímeras ya no existen.

Flujo: Cifrado Híbrido RSA + AES

✉️ EMISOR
① os.urandom(32)
→ clave_aes (256 bits)
↓
② AES-256-GCM cifra datos
→ datos_cifrados + tag + nonce
↓
③ RSA-OAEP cifra clave_aes
→ clave_cifrada (256 B)
↓
📤 clave_cifrada ‖ nonce ‖ tag ‖ datos_cifrados
⟶
📥 RECEPTOR
① RSA privada descifra clave_cifrada
→ clave_aes
↓
② AES-256-GCM descifra datos
+ verifica tag (autenticidad)
↓
✅ Datos originales recuperados

RSA opera solo sobre 32 bytes (la clave AES). AES opera sobre los datos reales. Lo mejor de ambos mundos.

Cifrado de Clave Simétrica con RSA

Patrón real de uso:

import os
from Crypto.Cipher import AES, PKCS1_OAEP
from Crypto.PublicKey import RSA
from Crypto.Hash import SHA256

# 1. Generar clave AES de sesión
clave_aes = os.urandom(32)  # AES-256

# 2. Cifrar datos con AES (rápido)
cipher_aes = AES.new(clave_aes, AES.MODE_GCM)
datos_cifrados, tag = cipher_aes.encrypt_and_digest(b"Datos confidenciales grandes...")

# 3. Cifrar la clave AES con RSA-OAEP (lento, pero solo 32 bytes)
public_key = RSA.import_key(open("recipient_public.pem").read())
cipher_rsa = PKCS1_OAEP.new(public_key, hashAlgo=SHA256)
clave_cifrada = cipher_rsa.encrypt(clave_aes)

# Transmitir: clave_cifrada + cipher_aes.nonce + tag + datos_cifrados

Errores Comunes en RSA

  • Usar PKCS#1 v1.5 para cifrado: Vulnerable a Bleichenbacher. Siempre usar OAEP
  • Clave privada sin passphrase: Si el archivo es robado, la clave es directamente utilizable
  • RSA "textbook" sin padding: Cifrado determinístico, malleable y fácilmente atacable
  • Exponente público e = 3: Si m³ < n, el cifrado es trivialmente reversible con raíz cúbica
  • Módulo compartido entre usuarios: Si dos usuarios comparten n pero tienen diferentes e, mensajes comunes pueden recuperarse con el algoritmo de Euclides extendido
  • No verificar la firma RSA: Solo comprobar que la función no lanzó excepción, sin validar que el hash coincide con el mensaje
  • Usar MD5 o SHA-1 con RSA: SHA-1 fue roto con colisiones (SHAttered, 2017). Usar SHA-256 o SHA-3 mínimo
  • Generar claves con entropía baja: En el boot de sistemas embebidos hay poca entropía — esperar o usar hardware RNG
  • Implementar RSA desde cero: Las operaciones de tiempo constante son difíciles. Usar OpenSSL, libsodium o cryptography

Casos de Uso

  • Certificados X.509 / PKI: RSA-2048/3072 para firmar certificados digitales en CAs
  • TLS/SSL: Autenticación de servidor (certificado); intercambio de claves ahora vía ECDHE
  • Firma de Software: RSA-PSS para verificar integridad de actualizaciones y binarios
  • PGP / GPG: Cifrado de correo asimétrico (en desuso frente a ECC moderno)
  • SSH: Autenticación de usuarios (aunque Ed25519 es preferido)
