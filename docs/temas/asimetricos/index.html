Cifrados Asimétricos

Criptografía de Clave Pública

El Problema

¿Por qué necesitamos criptografía asimétrica?

Distribución de Claves Simétricas

Con cifrado simétrico, cada par de usuarios necesita su propia clave secreta.

Para N usuarios hacen falta N(N−1)/2 claves:

  • 10 usuarios → 45 claves
  • 100 usuarios → 4,950 claves
  • 1,000 usuarios → 499,500 claves

¿Y cómo distribuyes esas claves de forma segura
sin un canal seguro previo?

¿Qué hacían los ejércitos antes de Internet para distribuir claves?

Simétrica vs Asimétrica

Aspecto Simétrica Asimétrica
Claves Una sola compartida Par pública / privada
Velocidad Muy rápida 100–1000× más lenta
Distribución Problema abierto Resuelto
Autenticación No directa Sí — firmas digitales
Uso típico Cifrado masivo de datos Intercambio de claves, firmas

La Solución

Un par de claves matemáticamente relacionadas

Clave Pública y Clave Privada

  • Clave pública — se comparte libremente.
    Cifra datos · verifica firmas
  • Clave privada — nunca sale de tu sistema.
    Descifra datos · genera firmas

La clave pública se deriva de la privada,
pero el proceso no se puede invertir en tiempo razonable.

Trapdoor Functions

La seguridad descansa en problemas fáciles en una dirección, inviables en la otra:

  • Factorización de enteros — base de RSA
    Multiplicar dos primos enormes: trivial. Factorizarlos: inviable.
  • Logaritmo discreto — base de DH / ElGamal
    Calcular gx mod p: rápido. Encontrar x dado gx: inviable.
  • Problema del punto en curvas elípticas — base de ECC
    Misma idea, claves 10× más cortas para igual seguridad.
¿Por qué "computacionalmente inviable" no significa "imposible"?

Historia

De la teoría al estándar global

El Nacimiento (1976–1985)

  • 1976 — Diffie & Hellman: "New Directions in Cryptography"
    Primera propuesta pública de intercambio de claves sin canal secreto previo
  • 1977 — RSA (Rivest, Shamir, Adleman)
    Primer algoritmo práctico de clave pública para cifrado y firmas
  • 1985 — Koblitz & Miller proponen ECC
    Seguridad equivalente a RSA con claves mucho más pequeñas

Internet y las Primeras Grietas (1991–2010)

  • 1991 — PGP: cifrado de correo para el público general
  • 1994 — Shor demuestra que una computadora cuántica rompe RSA → nace la amenaza cuántica
  • 1995 — Netscape SSL con RSA → base de HTTPS
  • 1998 — Bleichenbacher: padding oracle contra RSA PKCS#1 v1.5
  • 2009 — Bitcoin usa ECDSA (secp256k1)
  • 2010 — Hack PS3: nonce reutilizado en ECDSA expone clave privada
¿Por qué la amenaza cuántica de 1994 no importó hasta hace poco?

La Era Post-Cuántica (2016–2024)

  • 2016 — NIST lanza concurso de estandarización PQC
  • 2018 — TLS 1.3 elimina RSA estático; solo ECDHE/DHE
  • 2024 — NIST publica primeros estándares PQC:
    • ML-KEM FIPS 203 — intercambio de claves
    • ML-DSA FIPS 204 — firmas digitales
    • SLH-DSA FIPS 205 — firmas basadas en hash

Tres Operaciones Fundamentales

Crifrado - Confidencialidad

  • Cualquiera cifra con la clave pública del destinatario
  • Solo el destinatario descifra con su clave privada
  • Garantiza que solo el receptor previsto puede leer el mensaje

Firma Digital - Autenticidad e Integridad

  1. Se calcula el hash del mensaje (SHA-256, SHA-3)
  2. El hash se firma con la clave privada del emisor
  3. El receptor verifica con la clave pública y recomputa el hash

Garantiza: autenticidad · integridad · no repudio

¿Por qué firmamos el hash y no el mensaje completo?

Intercambio de Claves DH / ECDH

  • Dos partes generan una clave compartida sobre un canal público — sin enviársela entre sí
  • Perfect Forward Secrecy (PFS): claves efímeras por sesión → comprometer la clave privada futura no expone sesiones pasadas
  • TLS 1.3 exige PFS — elimina el intercambio estático con RSA

En la Práctica

Nadie usa solo criptografía asimétrica para cifrar datos

Cifrado Híbrido

La criptografía asimétrica es 100–1000× más lenta que AES.

  1. RSA / ECDH negocia una clave de sesión simétrica (ej. AES-256)
  2. AES cifra los datos con esa clave efímera
  3. El receptor usa su clave privada para recuperar la clave de sesión

Dónde ocurre esto hoy: TLS 1.3 · PGP · Signal Protocol · HTTPS

¿Cuándo tiene sentido cifrar directamente con RSA?

Aplicaciones Reales

  • HTTPS / TLS 1.3: ECDHE (X25519) para intercambio · ECDSA/RSA para certificados
  • SSH: Ed25519 como algoritmo recomendado (sobre RSA-4096)
  • Blockchain: ECDSA secp256k1 (Bitcoin, Ethereum) · EdDSA (Solana)
  • PGP / GPG: Preferir ECC (ed25519 + cv25519) sobre RSA legacy
  • Signal / WhatsApp: X3DH + Double Ratchet — ECDH efímero + ratchet simétrico
  • PKI / X.509: Base de toda la identidad digital en Internet

Errores Comunes

Donde han fallado sistemas reales

Errores de Protocolo

  • RSA con PKCS#1 v1.5: Vulnerable al ataque Bleichenbacher (1998) → usar RSA-OAEP
  • Nonce reutilizado en ECDSA: Sony PS3 (2010) — reutilizar k expone la clave privada completamente
  • Claves cortas: RSA-1024 rota en 2010. Mínimo: RSA-2048; recomendado: RSA-3072 o ECC-256
  • No verificar certificados TLS: Bypass total de autenticación — MITM invisible

Errores de Implementación

  • Clave privada en el repositorio: Exposición directa e irreversible
  • Sin passphrase en disco: Clave privada accesible a cualquiera con acceso al sistema
  • Sin revocación (CRL / OCSP): Certificados comprometidos permanecen activos
  • Algoritmos obsoletos: MD5, SHA-1, RSA sin padding, Dual_EC_DRBG (backdoor NSA)

Ataques de Canal Lateral

Una implementación correcta en papel puede filtrar información a través de tiempo de ejecución · consumo de energía · radiación EM.

  • Timing attack: medir tiempo de descifrado RSA puede revelar la clave privada
  • Se requieren implementaciones de tiempo constante
  • Librerías auditadas: libsodium · OpenSSL 3.x

Regla de oro: "Don't roll your own crypto."

¿Qué información puede revelar que una operación tarda 0.5 ms vs 0.7 ms?

La Amenaza Cuántica

El Algoritmo de Shor

  • Una computadora cuántica suficientemente grande puede factorizar RSA y resolver el logaritmo discreto en tiempo polinomial
  • Esto rompería RSA, DH, ECDH, ECDSA — la base de Internet seguro actual
  • Grover debilita AES pero no lo rompe — basta duplicar el tamaño de clave

Harvest Now, Decrypt Later

Adversarios con recursos ya almacenan tráfico cifrado hoy para descifrarlo cuando existan computadoras cuánticas capaces.

  • Datos con valor confidencial de +10 años están en riesgo ahora
  • La ventana de migración se cierra antes de lo que parece
  • NIST recomienda migrar a PQC antes de 2030
¿Qué sistemas tienen mayor urgencia de migrar a PQC primero?

Criptografía Post-Cuántica (PQC)

Estándares NIST 2024 — diseñados para resistir ataques cuánticos:

  • ML-KEM (FIPS 203) — Intercambio de claves (sucesor de Kyber)
  • ML-DSA (FIPS 204) — Firmas digitales (sucesor de Dilithium)
  • SLH-DSA (FIPS 205) — Firmas basadas en hash (SPHINCS+)

TLS 1.3 ya soporta ML-KEM en experimentos. Chrome y Firefox lo están adoptando.

Resumen

Lo Esencial

  • Par de claves resuelve la distribución segura sin canal previo
  • Tres usos: cifrar · firmar · intercambiar claves
  • Nunca solo asimétrico para datos: usar cifrado híbrido
  • ECC > RSA para nuevos sistemas (mismo nivel, claves pequeñas)
  • PFS obligatorio — TLS 1.3 ya lo exige
  • Migrar a PQC antes de 2030
  • No implementes tu propio crypto
