¿Qué es una Función Hash?

Una función hash criptográfica transforma cualquier entrada de tamaño arbitrario en una "huella digital" de tamaño fijo, de forma determinista e irreversible.

Entrada Arbitraria

Acepta desde un byte hasta terabytes. Un tweet y un vídeo 4K producen hashes del mismo tamaño.

Salida Fija

SHA-256 siempre produce 256 bits (64 caracteres hex). Sin importar el tamaño de la entrada.

Unidireccional

No existe operación inversa matemáticamente eficiente. A diferencia de RSA, no hay clave para revertirlo.

Las 5 Propiedades Fundamentales

Toda función hash criptográfica segura debe cumplir estas cinco propiedades.

Propiedad 1
Resistencia a Pre-imagen (Unidireccionalidad)
Dado el hash h, es computacionalmente imposible encontrar el mensaje m tal que H(m) = h. Garantiza que las contraseñas hasheadas no puedan revertirse.
Propiedad 2
Determinismo
La misma entrada siempre produce exactamente el mismo hash. SHA256("Hola") será idéntico en cualquier computadora, en cualquier momento.
Propiedad 3
Efecto Avalancha
Cambiar un solo bit en la entrada altera alrededor del 50% de los bits en la salida. Un espacio de diferencia entre "Hola" y "hola" produce hashes completamente distintos.
Propiedad 4
Resistencia a Colisiones
Es computacionalmente inviable encontrar dos mensajes distintos m₁ ≠ m₂ que produzcan el mismo hash H(m₁) = H(m₂). MD5 y SHA-1 han fallado aquí.
Propiedad 5
Resistencia a Segunda Pre-imagen
Dado un mensaje m₁, no se puede encontrar m₂ ≠ m₁ con el mismo hash. Garantiza que un atacante no pueda sustituir un documento firmado por otro con el mismo hash.
¿Por qué los hashes son unidireccionales? A diferencia de RSA donde la operación de descifrado es matemáticamente la inversa del cifrado (usando la clave privada), las funciones hash mezclan los bits del mensaje de forma tan no-lineal —usando XOR, rotaciones, módulos y funciones de compresión iterativas (Merkle-Damgård o Sponge)— que no existe operación inversa algebraicamente tratable. Es como intentar reconstruir un huevo frito a partir de un omelet.

Ataques y Mitigaciones

Conocer los vectores de ataque es esencial para elegir la mitigación correcta.

Rainbow Tables

Tablas precalculadas de pares hash → texto. Si tu base de datos se filtra, el atacante busca el hash y recupera la contraseña original en microsegundos.

¿Por qué funciona? SHA-256("password") siempre da el mismo hash, y ese hash ya está en la tabla.

Mitigación Salt aleatorio único por usuario (os.urandom(32)). El salt hace que SHA-256("salt123" + "password") sea único, invalidando toda la tabla precalculada.
Length Extension Attack

SHA-1, SHA-256, SHA-512 (Merkle-Damgård) permiten calcular H(secreto || mensaje || extensión) sin conocer el secreto, solo conociendo H(secreto || mensaje).

¿Por qué funciona? El estado interno del hash al final de un mensaje puede usarse como punto de partida para extender el mensaje.

Mitigación Usar HMAC en lugar de H(secreto || mensaje). HMAC realiza dos pasadas que eliminan esta vulnerabilidad. SHA-3 no es vulnerable (Sponge construction).
Fuerza Bruta GPU

Una RTX 4090 calcula ~22 mil millones de SHA-256 por segundo. Con diccionarios y reglas, puede quebrar contraseñas comunes en segundos.

¿Por qué funciona? Las GPU tienen miles de cores paralelos optimizados para exactamente el tipo de cómputo que SHA-256 requiere.

Mitigación Argon2id con memoria adaptativa (≥64MB). La GPU necesita esa memoria para cada hash, y con 4GB de VRAM solo puede calcular ~60 hashes en paralelo en lugar de 22 billones.

HMAC — Autenticación de Mensajes

SHA-256 verifica integridad (¿el archivo cambió?), pero HMAC añade autenticidad (¿quién lo creó?).

Solo Hash (SHA-256)

Verifica que los datos no cambaron en tránsito. Pero cualquiera puede modificar los datos y recalcular el hash. Sin clave secreta = sin autenticidad.

H(mensaje) → integridad [ok]
¿quién lo firmó? [desconocido]

HMAC (Hash + Clave)

Combina una clave secreta compartida con el mensaje. Solo quien conoce la clave puede producir o verificar el MAC. Integridad + autenticidad.

HMAC(K, mensaje) → integridad [ok]
y autenticidad [ok] (solo K puede firmarlo)

Construcción HMAC

HMAC(K, m) = H( (K' ⊕ opad) ‖ H( (K' ⊕ ipad) ‖ m ) )
K'

Clave K con padding al tamaño del bloque hash (64 bytes para SHA-256)

ipad / opad

Constantes de relleno interior (0x36) y exterior (0x5c). Crean dos sub-claves distintas.

2 pasadas

Las dos pasadas eliminan la vulnerabilidad de length extension. La pasada exterior envuelve la interior.

Buenas Prácticas de Seguridad

Reglas críticas que separan el código seguro del vulnerable.

Nunca SHA-256 directo para contraseñas

SHA-256 es demasiado rápido (22B/seg en GPU). Usa Argon2id que es memory-hard y GPU-resistant. Configuración mínima OWASP: m=65536, t=3, p=4.

Nunca construir MAC como H(secreto ‖ mensaje)

Vulnerable a Length Extension Attack. Siempre usa HMAC: hmac.new(key, msg, hashlib.sha256).hexdigest().

Salt aleatorio único por usuario

Usar os.urandom(32) para generar un salt criptográficamente seguro. Almacenar el salt junto al hash (es público, no secreto). Invalida rainbow tables.

Comparación en tiempo constante

Usa hmac.compare_digest(hash_a, hash_b) en lugar de ==. El operador == retorna al primer byte diferente, permitiendo timing attacks que revelan cuántos bytes coinciden.

Migrar de MD5/SHA-1 ya

MD5 y SHA-1 tienen colisiones prácticas demostradas. SHA-1 fue eliminado de TLS 1.3. Si los usas para integridad o firmas, migra a SHA-256 o BLAKE3 inmediatamente.

SHA-3 como Plan B

Si SHA-2 fuera comprometido, SHA-3 (Keccak) está disponible. Usa una construcción Sponge completamente diferente, por lo que vulnerabilidades en SHA-2 no afectarían a SHA-3.

Aplicaciones en el Mundo Real

Las funciones hash están en todas partes del ecosistema digital moderno.

Integridad de Archivos
Distribuciones Linux publican sha256sum ubuntu.iso para verificar que la descarga no fue corrompida o manipulada.
Protección de Contraseñas
Las bases de datos almacenan argon2id(salt + password), nunca la contraseña en texto plano. La contraseña nunca sale del cliente.
Firmas Digitales
RSA y ECDSA no cifran el documento completo, cifran el hash del documento. Mucho más eficiente y seguro.
Blockchain / Bitcoin
SHA-256 encadena bloques y es la base del Proof of Work. Cada bloque contiene el hash del bloque anterior, creando inmutabilidad.
Git
Cada commit, árbol y blob es identificado por su SHA-1 (migrando a SHA-256). El hash es la identidad del objeto en Git.
Detección de Malware
Antivirus y VirusTotal identifican amenazas por el hash del archivo. Una modificación de un byte genera un hash completamente diferente.
Merkle Trees
Verificación O(log n) de elementos en conjuntos masivos. Usado en Bitcoin, Git, IPFS, ZFS y certificados de transparencia TLS.
JWT / OAuth
Los JSON Web Tokens usan HMAC-SHA256 o RSA-SHA256 para garantizar que el payload no fue alterado entre emisión y verificación.
TLS / HTTPS
Los certificados SSL/TLS son firmados con SHA-256. La huella (fingerprint) del certificado permite verificar la identidad del servidor.

Ejemplos de Código

Implementaciones limpias en Python siguiendo las mejores prácticas de seguridad.

Python — SHA-256 para integridad de archivos 
import hashlib

# Hash de un string simple
def hash_string(texto: str) -> str:
    return hashlib.sha256(texto.encode('utf-8')).hexdigest()

# Hash de archivos grandes (sin cargar todo en RAM)
def hash_file(path: str) -> str:
    h = hashlib.sha256()
    with open(path, 'rb') as f:
        for chunk in iter(lambda: f.read(65536), b''):
            h.update(chunk)   # actualizar en chunks de 64KB
    return h.hexdigest()

# Verificar integridad
def verify_file(path: str, expected_hash: str) -> bool:
    actual = hash_file(path)
    import hmac
    # Comparación en tiempo constante (previene timing attacks)
    return hmac.compare_digest(actual, expected_hash)

# Uso
print(hash_string("Hola mundo"))
# → b94f6f125c79e3a5ffaa826f584c10d52ada669e6762051b826b55776d05a8a

print(hash_file("ubuntu-24.04.iso"))
# → (verificar contra sha256sum publicado por Ubuntu)
Python — Contraseñas con Argon2id (OWASP) 
# pip install argon2-cffi
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError

# Configuración mínima recomendada por OWASP 2024
ph = PasswordHasher(
    time_cost=3,      # iteraciones (≥3)
    memory_cost=65536, # 64 MB de RAM requeridos
    parallelism=4,     # hilos paralelos
    hash_len=32,       # 256 bits de hash
    salt_len=16        # salt aleatorio automático
)

# Hashear (genera salt aleatorio automáticamente)
def hash_password(password: str) -> str:
    return ph.hash(password)
    # → "$argon2id$v=19$m=65536,t=3,p=4$..."

# Verificar contraseña
def verify_password(stored_hash: str, password: str) -> bool:
    try:
        ph.verify(stored_hash, password)
        # Re-hashear si los parámetros cambiaron (backward compat)
        if ph.check_needs_rehash(stored_hash):
            return True, hash_password(password)
        return True, None
    except VerifyMismatchError:
        return False, None

# Uso
hash_stored = hash_password("contraseña_usuario")
ok, new_hash = verify_password(hash_stored, "contraseña_usuario")
print(ok)  # True

# NUNCA hacer esto:
# import hashlib; hashlib.sha256(password.encode()).hexdigest()  ← VULNERABLE
Python — HMAC-SHA256 para autenticación de mensajes 
import hmac
import hashlib
import os

# Generar una clave secreta compartida
SECRET_KEY = os.urandom(32)  # 256 bits aleatorios

# Firmar un mensaje
def sign_message(message: str, key: bytes) -> str:
    return hmac.new(
        key,
        message.encode('utf-8'),
        hashlib.sha256
    ).hexdigest()

# Verificar en tiempo constante (previene timing attacks)
def verify_message(message: str, signature: str, key: bytes) -> bool:
    expected = sign_message(message, key)
    # hmac.compare_digest evita ataques de timing
    return hmac.compare_digest(expected, signature)

# Ejemplo: autenticar webhook de API
payload = "user_id=42&action=transfer&amount=100"
sig = sign_message(payload, SECRET_KEY)

# El receptor verifica:
print(verify_message(payload, sig, SECRET_KEY))  # True
print(verify_message("user_id=42&action=transfer&amount=9999", sig, SECRET_KEY))  # False

# NUNCA hacer esto:
# H(secret || message)  ← vulnerable a Length Extension Attack
# hash_a == hash_b       ← vulnerable a Timing Attack (usar compare_digest)
Python — BLAKE3 para hashing ultrarrápido 
# pip install blake3
import blake3

# Hash simple — 5-10x más rápido que SHA-256
def hash_string_b3(texto: str) -> str:
    return blake3.blake3(texto.encode()).hexdigest()

# Hash de archivo con paralelismo (BLAKE3 es internamente paralelo)
def hash_file_b3(path: str) -> str:
    h = blake3.blake3()
    with open(path, 'rb') as f:
        for chunk in iter(lambda: f.read(1048576), b''):  # 1 MB chunks
            h.update(chunk)
    return h.hexdigest()

# BLAKE3 como KDF (derive_key) — recomendado sobre HKDF con SHA-256
def derive_key(context: str, material: bytes) -> bytes:
    return blake3.blake3(
        material,
        derive_key_context=context
    ).digest(length=32)

# Cuándo usar BLAKE3 vs SHA-256:
# BLAKE3: integridad de archivos, hashing de datos, CDN content-addressed storage
# SHA-256: cuando necesitas compatibilidad estándar (TLS, firmas X.509, Bitcoin)
# BLAKE3 NO es adecuado para contraseñas (usar Argon2id)

print(hash_string_b3("Hola mundo"))
