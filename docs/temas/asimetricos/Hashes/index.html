¿Qué es una Función Hash?

La Caja Negra criptográfica

Una función hash toma cualquier cantidad de datos — un archivo de 1 byte o de 100 GB — y produce siempre una huella digital de tamaño fijo.

  • Podemos hashear cualquier cosa (texto, imagen, video)
  • Siempre sale exactamente el mismo volumen (ej. 256 bits)
  • No se puede "extraer": el resultado no revela nada sobre los datos de entrada

La diferencia clave con RSA

En RSA el cifrado es reversible con la clave correcta.

En una función hash la transformación es unidireccional por diseño — nunca se puede revertir. 

import hashlib

# El mismo input SIEMPRE produce el mismo hash
print(hashlib.sha256(b"hola").hexdigest())
# a5cf06e0dd55e88f4f1b9b55ac5db8e28bf62a3e671048e92e1c9a24b0428027

# Un solo bit diferente => hash completamente distinto (efecto avalancha)
print(hashlib.sha256(b"Hola").hexdigest())
# 1e3f...  completamente diferente

Propiedades

  • Unidireccionalidad (Pre-image resistance):
    Dado h, es computacionalmente inviable encontrar m tal que H(m) = h. Protege contraseñas almacenadas.
  • Determinismo:
    La misma entrada siempre produce el mismo hash. Sin esto, no se podría verificar nada.
  • Efecto Avalancha:
    Cambiar 1 bit de la entrada cambia ~50% de los bits del hash. "hola" y "Hola" producen hashes completamente distintos.
  • Resistencia a colisiones (Collision resistance):
    Computacionalmente inviable encontrar m₁ ≠ m₂ con H(m₁) = H(m₂). Evita falsificación de documentos.
  • Resistencia a la segunda pre-imagen (2nd pre-image):
    Dado m₁, inviable encontrar m₂ ≠ m₁ con H(m₁) = H(m₂). Evita sustitución de un documento por otro.
  • Rapidez:
    Cálculo eficiente para cualquier tamaño de entrada.

Algoritmos Hash Modernos

MD5 — No usar para seguridad

  • Desarrollado en 1991 por Ron Rivest (la R de RSA).
  • Produce un valor de hash de 128 bits (32 hex)
  • Colisiones prácticas desde 2004. Flame malware (2012) usó colisión MD5 para falsificar cert de Microsoft.
  • Solo aceptable para checksum rápido sin implicaciones de seguridad.

SHA-1 — Obsoleto

  • Desarrollado en 1995 por NSA/NIST.
  • Produce 160 bits (40 hex)
  • SHAttered (Google, 2017): primera colisión práctica. Dos PDFs distintos con el mismo SHA-1.
  • No usar en nuevos sistemas. Removido de TLS 1.3. Navegadores rechazan certificados con SHA-1.

SHA-256 (SHA-2) — El estándar actual

  • Desarrollado en 2001 por NSA/NIST.
  • Produce 256 bits (64 hex)
  • Sin colisiones conocidas. Ampliamente analizado.
  • Usado en: Bitcoin, TLS, SSH, PGP moderno, certificados HTTPS.
  • Usar por defecto para integridad y firmas.

SHA-3 (Keccak) — El plan B

  • Estandarizado en 2015. Diseño interno radicalmente distinto a SHA-2.
  • Produce 224, 256, 384 o 512 bits.
  • Diferente familia que SHA-2. Si se descubre una vulnerabilidad en SHA-2, SHA-3 no se ve afectado.
  • Usado en Ethereum (keccak256), aplicaciones críticas de seguridad.

BLAKE3 — El más rápido

  • Desarrollado en 2020. Produce 256 bits por defecto (configurable).
  • 5-10x más rápido que SHA-256 en hardware moderno. Paralelizable — aprovecha múltiples núcleos.
  • Usado en sistemas de archivos (Btrfs), herramientas de build.
  • Aún en proceso de adopción para estándares de seguridad críticos.

El caso especial: hashes de contraseñas

Trampa conceptual: si SHA-256 es seguro, ¿por qué no usarlo para contraseñas? El problema es que es demasiado rápido.

Una RTX 4090 calcula 22 mil millones de SHA-256/segundo. Una contraseña de 8 chars se crackea en segundos.

Ataques a Funciones Hash

Rainbow Tables

  • Tablas precalculadas que mapean hashes a sus textos planos originales.
  • Si el sitio usó SHA-256 directamente sobre la contraseña, el atacante consulta la tabla y encuentra la original casi instantáneamente.
  • HaveIBeenPwned tiene miles de millones de pares (hash, contraseña) de filtraciones reales.
  • Mitigación: Salt. Un valor aleatorio único por usuario invalida cualquier tabla precalculada.

Salt — La defensa contra Rainbow Tables

import hashlib, os

# Sin salt — vulnerable a rainbow tables
hash_sin_salt = hashlib.sha256(b"mi_password").hexdigest()
# 5e884898da280471...  (en cualquier rainbow table)

# Con salt — invulnerable a tablas precalculadas
salt = os.urandom(32)  # 32 bytes aleatorios únicos por usuario
hash_con_salt = hashlib.sha256(salt + b"mi_password").hexdigest()
# Almacenar: salt + hash_con_salt

# El salt no es secreto, se almacena junto al hash
# Su propósito es hacer cada hash único, no secreto

Usar Argon2id en lugar de SHA+salt para contraseñas: maneja el salt automáticamente y añade resistencia a GPU/ASIC.

Length Extension Attack

  • SHA-1, SHA-256 y SHA-512 (familia Merkle-Damgård) son vulnerables a un ataque de extensión de longitud.
  • Si conoces H(mensaje) pero no el mensaje, puedes calcular H(mensaje || padding || extension) sin conocer el mensaje original.
  • Ejemplo: Una API que protege parámetros con MAC = SHA256(secret || params) es vulnerable si el atacante puede añadir parámetros extras.

Demostración del ataque

# VULNERABLE: MAC construido concatenando secreto
def mac_vulnerable(secreto, mensaje):
    return hashlib.sha256(secreto + mensaje).hexdigest()

# Un atacante que conoce mac_vulnerable(secreto, "amount=100")
# puede calcular mac_vulnerable(secreto, "amount=100&admin=true")
# sin conocer el secreto — usando herramientas de length extension

# SEGURO: HMAC está diseñado para evitar este ataque
import hmac
def mac_seguro(secreto, mensaje):
    return hmac.new(secreto, mensaje, hashlib.sha256).hexdigest()
# HMAC usa dos pasadas de hash que eliminan la vulnerabilidad

Regla: Para MACs, siempre HMAC, nunca H(secreto || mensaje).

Fuerza Bruta con GPU

  • RTX 4090: ~22 billion SHA-256/segundo
  • Contraseña de 8 chars (minúsculas + números): ~3 billones de combinaciones → crackeada en segundos con SHA-256
  • Argon2id con configuración mínima OWASP (~64MB RAM, 3 iteraciones): menos de 100 hashes/segundo en GPU — hace el ataque económicamente inviable

HMAC — Hash-Based Message Authentication Code

SHA-256 verifica integridad (¿fue modificado?), pero no autenticidad (¿quién lo generó?). Para esto existe HMAC.


  • Integridad: el mensaje no fue alterado
  • Autenticidad: quien generó el MAC conoce la clave secreta

HMAC(K, m) = H((K' ⊕ opad) || H((K' ⊕ ipad) || m))

import hmac
import hashlib

secreto = b"clave_secreta_compartida"
mensaje = b"amount=100&recipient=alice"

# Generar MAC
mac = hmac.new(secreto, mensaje, hashlib.sha256).hexdigest()
print("HMAC-SHA256:", mac)

# Verificar MAC (comparación de tiempo constante — evita timing attack)
mac_recibido = "..."  # MAC del mensaje recibido
if hmac.compare_digest(mac, mac_recibido):
    print("Mensaje auténtico e íntegro")
else:
    print("Mensaje alterado o MAC inválido")

# IMPORTANTE: hmac.compare_digest previene timing attacks
# No usar mac == mac_recibido (revela info por tiempo de ejecución)

Aplicaciones

Los hashes están en casi todo lo que usan a diario.

Integridad de Archivos y Datos

Verifican que el archivo recibido es completo, no fue alterado y no está corrompido. 

# Verificar descarga de ISO de Ubuntu
sha256sum ubuntu-24.04.iso
# Comparar con el hash publicado en el sitio oficial

Usado para: archivos .zip, .tar, ISOs, firmware, paquetes (npm, pip, apt)

Protección de Contraseñas

  • Ningún sistema serio almacena contraseñas en texto plano. Almacena el hash + salt (Argon2id).
  • Verificación: se hashea la contraseña ingresada y se compara el resultado. La contraseña original nunca se almacena.

Firmas Digitales — La conexión con RSA

No se firma el documento completo con RSA — eso sería lento para archivos grandes. Se firma el hash del documento.

TLS 1.3 solo acepta SHA-256 y SHA-384 — SHA-1 completamente eliminado.

Blockchain

Bitcoin usa SHA-256 para encadenar bloques y el mecanismo de Proof of Work. Cambiar una transacción cambia el hash del bloque, que cambia el del siguiente — invalidando toda la cadena.

Ethereum usa Keccak-256 (SHA-3 no estándar).

Git — Lo usan todos los días

Cada commit, árbol y blob en Git tiene un identificador SHA-1 (en proceso de migración a SHA-256). El git log que usan a diario está basado en hashes.

Detección de Malware

  • Los antivirus identifican amenazas por el hash del archivo, no por su nombre.
  • Listas públicas de hashes de malware: VirusTotal, NSRL.
  • PhotoDNA de Microsoft usa hashes perceptuales para detectar contenido ilegal en imágenes, incluso con modificaciones menores.

Merkle Trees

  • Árbol binario donde cada nodo contiene el hash de sus hijos.
  • La raíz (Merkle root) representa de forma compacta e íntegra todo el árbol.
  • Verifica que un elemento pertenece al árbol sin descargarlo completo — O(log n) verificación.
  • Usado en: Bitcoin (transacciones en bloques), Git, IPFS, ZFS.

Implementación

SHA-256 en Python

import hashlib

mensaje = "Hola, mundo"
hash_sha256 = hashlib.sha256(mensaje.encode()).hexdigest()
print("SHA-256:", hash_sha256)

# Para archivos grandes: usar update() para no cargar todo en memoria
sha256 = hashlib.sha256()
with open("archivo_grande.bin", "rb") as f:
    for chunk in iter(lambda: f.read(65536), b""):
        sha256.update(chunk)
print("SHA-256 del archivo:", sha256.hexdigest())

Contraseñas con Argon2id (Recomendado)

from argon2 import PasswordHasher, exceptions

ph = PasswordHasher()
# Configuración OWASP mínima por defecto: m=65536, t=3, p=4

# Registrar contraseña
hash_almacenado = ph.hash("mi_super_contraseña")
print("Hash Argon2id:", hash_almacenado)

# Verificar contraseña
try:
    ph.verify(hash_almacenado, "mi_super_contraseña")
    if ph.check_needs_rehash(hash_almacenado):
        nuevo_hash = ph.hash("mi_super_contraseña")
        # Almacenar nuevo_hash en la BD
    print("Acceso concedido")
except exceptions.VerifyMismatchError:
    print("Contraseña incorrecta")
except exceptions.VerificationError:
    print("Error en verificación")

HMAC para APIs (Tiempo Constante)

import hmac
import hashlib
import secrets

api_secret = secrets.token_bytes(32)

def firmar_request(secreto, payload: bytes) -> str:
    return hmac.new(secreto, payload, hashlib.sha256).hexdigest()

def verificar_request(secreto, payload: bytes, firma_recibida: str) -> bool:
    firma_esperada = firmar_request(secreto, payload)
    # compare_digest: tiempo constante — previene timing attack
    return hmac.compare_digest(firma_esperada, firma_recibida)

payload = b"POST /transfer amount=100 to=bob"
firma = firmar_request(api_secret, payload)
assert verificar_request(api_secret, payload, firma)

La conexión con lo que viene

Los hashes ayudan a unir los algoritmos criptográficos.


  • Firmas digitales: RSA firma el hash del documento.
  • Certificados TLS: SHA-256 aparece en todas partes.
  • Blockchain: SHA-256 es el núcleo de Proof of Work.
  • Git: cada objeto es identificado por su hash.
